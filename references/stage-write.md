# write 단계, 장면 설계와 초안

> **묻기와 기록.** 이 문서에서 사용자에게 묻는 자리와 원장에 `gate:`·`waiver:` 줄을 남기는 일은 지휘(`<스킬>/SKILL.md`)가 한다. 서브 에이전트로 실행 중이면 그 자리에서 작업을 저장하고 `need_user`로 돌아간다. 서브 에이전트 없이(Codex 등) 이 문서를 직접 수행할 때는 직접 묻고 기록한다. `stage:`·`note:` 줄은 단계를 수행한 쪽이 쓴다.

두 단계로 나눈다. 1단계는 작품 전체를 한 번에 그리는 설계, 2단계는 BLACK의 목소리로 한 장씩 깊게 쓰는 집필이다. 둘을 섞으면 구조가 흔들리거나 페르소나가 무너진다.

규약은 `<스킬>/references/workflow.md`, 작품 값은 `book-toc.md` 블록을 따른다. 이 문서에 숫자를 적지 않는다.

## 0. 준비

1. 원장에 `stage: research done`이 있는지 확인한다. 없으면 research 단계를 안내하고 종료한다.
2. book-toc 전체(블록, 페르소나, 문체 9원칙, 명시 금지 항목)와 통과본 `01_test/<run>/storyline.md`를 끝까지 읽는다.
3. 작가와 화자는 다른 층이다. BLACK은 9원칙으로 쓰고, 그 안에서 화자(블록 `narrator`)가 자기 시선으로 본다. 1인칭이면 화자는 서술문에서 자기 이름을 주어로 쓰지 않는다.
4. 한 줄로 알린다: `입력: storyline 통과본 + 01_research-notes.md / 출력: 02_outline.md, 03_draft-v1.md`.

## 1. 이어하기

| 상태 | 시작 지점 |
|---|---|
| `02_outline.md` 없음 | 1단계 |
| outline 있음, 초안 없음 | 2단계 첫 장 |
| 초안에 일부 장만 있음 | 빠진 첫 장부터 이어 붙인다 |
| 완료 기준 충족 | "review 단계로 진행하세요" |

초안의 장 존재 여부는 블록 `chapters`의 헤딩(`# <no>장. <title>`)으로 판정한다.

## 2. 1단계, 장면 설계 → `02_outline.md`

```
# 장면 설계서
## 분량 분배
| 장 | 매수(블록 pages) | 글자 수(pages × chars_per_page) | 시각 닻 |
## <no>장. <title>     (블록 chapters 순서대로 반복)
### 진입 동작        첫 문장이 될 동작·사물 한 줄
### 비트 4~6개       비트마다 대략 글자 수
### 사용할 리서치 자료  노트의 범주·항목 이름
### 위트 자리 후보    블록 wit 범위만큼, 출처 표기. zero_zones에 걸리면 0
### 마지막 한 줄 초고   storyline에 장별 마지막 줄이 있으면 그대로
## 인물 시트          블록 characters 전원 (행동 패턴, 손버릇, 재등장 자리)
## 시점·시제 정책      블록 narrator 기준. 화자가 모르는 정보 목록
## 시각 닻 회수 계획    블록 anchors의 장 배치와 최소 횟수를 장별로 나눈다
## 명시 금지 체크리스트  book-toc "명시 금지 항목" 그대로
```

분량 원칙: 장별 매수는 블록 `chapters[].pages`를 따른다. 비트 합산이 장 목표의 95~105% 안에 들어오게 설계한다.

예시(『점수표』): 진입 동작 "휠체어가 312호로 들어선다", 마지막 한 줄 초고 "그가 점을 찍은 자리에 나도 점을 찍었다."

## 3. 2단계, 초안 → `03_draft-v1.md`

### 진행 방식 (한 번만 묻는다)

시작할 때 한 번 묻는다: "(a) 장마다 확인하며 쓸까요, (b) 끝까지 쓰고 한 번에 보여 드릴까요?" 응답을 원장에 `gate: write-mode → <a|b>`로 남긴다. (b)여도 장마다 호출은 나눈다.

### 장 단위 호출

- 한 호출에 한 장만 쓴다. 다음 호출은 초안의 마지막 줄을 읽고 다음 장 헤딩부터 이어 붙인다. 같은 장을 두 번 쓰지 않는다.
- 장편(`structure_mode: "part"`)이면 부 파일(`03_draft-v1-part<n>.md`)로 나눈다(workflow.md 5절).

### 매 장 시작 전 9원칙 점검

단문(블록 `style.avg_sentence_chars_max`), 단락(`style.paragraph_lines`), 마지막 한 줄은 동작·사물, 위트(`wit` 범위와 `zero_zones`), 일상 비유, 감정 직접 노출 금지, 시점 안정, 번역투 금지, 주술 호응.

### 작성 규칙

- workflow.md 6절 본문 범용 규칙 전부.
- outline의 비트와 마지막 한 줄을 따른다. 바꾸려면 outline을 먼저 고치고 이유를 남긴다.
- 인물 정보는 outline 인물 시트와 storyline 통과본만 쓴다. 즉흥 디테일 금지.
- 장 밖 섹션(작가의 말, 서평 등)은 블록 `back_matter`에 이름이 있을 때만, 마지막 장 뒤에 `# <이름>` 헤딩으로 쓴다.

### 호출 끝 보고 (네 줄)

1. 어디까지 썼는지
2. 누적 글자 수와 매수 (블록 `chars_per_page` 기준)
3. 그 장의 마지막 한 줄
4. 다음 시작 헤딩

## 4. 완료 기준

전 장을 쓴 뒤 검증기를 돌린다.

```
python3 <스킬>/scripts/validate_draft.py --run <run> --draft 02_draft/<run>/03_draft-v1.md            # 단편
python3 <스킬>/scripts/validate_draft.py --run <run> --draft 02_draft/<run>/03_draft-v1-part*.md      # 장편: 부 파일 전부
```

FAIL 0이면 완료다. WARN과 MANUAL 항목은 review 단계로 넘긴다. FAIL이 있으면 해당 장만 고친다. 완료하면 원장에 `stage: write done <날짜>`를 남기고 "review 단계로 리뷰 사이클을 시작하세요"라고 안내한다.
